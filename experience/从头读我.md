# 从头读我

这是一座**空库**，工具齐、账齐、卡是 0 张。它是给你从零开始记的，不是坏包。

## 四类东西，各管一段

| 位置 | 装什么 | 怎么读 |
|---|---|---|
| 库根 `*.md`（除模板） | 经验卡：一个坑一张 | `recall.py search 关键词` |
| `current-work-state.md` | 语义层：现在做到哪 | `recall.py state` |
| `缺陷台账_*.md` / `发版流水_*.md` | 编年史：谁在什么时候改了什么 | `recall.py log status` |
| `memory/` | 过程记忆：对话里发生的事 | `recall.py mem search --q 关键词` |

## 第一次用，四步

1. `python .user_skills/experience-recall/自检.py` —— 应报「能用（空库）」，退出码 0。
2. 写第一张卡：照 `模板_经验卡.md` 造一个 .md 放库根，或直接问工具怎么写。
3. `recall.py build_index` —— 建检索索引，之后 `search` 才准。
4. `recall.py state --add-line "..."` —— 写下第一件在办的事。

## 三件「看起来像坏了、其实是正常」的事

1. **闸起不来**：`recall.py gate` 在 0 卡库上会报「GATE 无法判定：0 根探针」并 exit 2。空闸不等于通过，这不是故障。
2. **探针批准表不在**：空库没有卡，就没有探针可批，`deploy_check.py` 会报「批准表不可用」。等你建了自己的卡并 `approve` 之后它才会绿。
3. **资产册是空的**：资产册是「本机扫描结果」，换台机器扫出来必然不同，所以包里故意不带。跑一次 `recall.py asset scan` 就有了。

## 一条硬规矩

**记账前先确认库在哪台机**：`recall.py where`。多台机器同时写一座库，号会撞、账会分叉；要么只让一台写，要么每台各用各的库。
