# 经验与记忆管理工具

> 也写作「记忆与经验管理工具」——两种叫法指同一件东西。

把踩过的坑、做过的判断、发过的版本，记成**本地可检索的资产**，而不是留在聊天记录里等着被滚走。

纯本地、离线、零依赖：只要有 Python 3，不用装包、不用联网、不用起服务。

---

## 它解决什么

聊天记录有三个毛病：会滚走、跨会话接不上、同一个坑反复踩。这个工具把"经验"拆成三样能查的东西：

| 层 | 装什么 | 形态 |
|---|---|---|
| **经验卡** | 一条可复用的判据：什么时候适用、怎么验证、什么时候失效 | 一张 `.md`，带探针 |
| **三本账** | 缺陷台账 / 发版流水 / 状态变更史 | 只追加，不改写 |
| **记忆** | 事件级的过程记录（哪天做了什么、为什么） | `.jsonl` |

它不做 RAG、不做向量检索、没有 UI、不联网。查是关键词加权匹配，结果是文件路径加片段——**能自己翻回去核对**，这是它和"AI 帮你回忆"的根本区别。

## 30 秒上手

```bash
# 1. 解压到任意空文件夹（解压出来就是这个结构，不用改）
unzip experience-recall.zip     # Windows 用 解压.ps1，别用资源管理器双击
cd 解压出来的目录

# 2. 自检
sh 自检.sh                      # Windows 双击 自检.cmd
```

看到 `能用（空库）` 且退出码 0，就装好了。

```bash
python .user_skills/experience-recall/recall.py search 关键词      # 查历史经验
python .user_skills/experience-recall/recall.py log status         # 账记到哪了
python .user_skills/experience-recall/recall.py stats              # 库里有多少东西
python .user_skills/experience-recall/recall.py mem search --q 关键词   # 查某件事的过程
python .user_skills/experience-recall/recall.py asset scan         # 把本机技能记成账
```

## 目录结构

两个文件夹必须**并排**放在同一个地方，层级不能拆：

```
./
├── 看这里.txt                  使用说明（中文，先看这个）
├── 自检.cmd / 自检.sh          装完跑一次
├── 解压.ps1                    Windows 专用解压（避免中文名乱码）
├── .user_skills/
│   └── experience-recall/      程序位：说明书 + recall.py + core/（记忆程序）
└── experience/                 仓库位：经验卡、三本账、记忆
    ├── memory/                 
    ├── 模板_经验卡.md
    └── 从头读我.md
```

程序靠"自己在哪"推算仓库在哪。**把两个文件夹摆平了（各自放到不相干的地方），程序不报错，但会跑去别处找库**——这是唯一需要小心的地方。

> Linux 上库固定在 `~/experience`（v6.41 起的布局）。如果你本机已经有一份旧库，程序会优先用旧的，包里的空库不会被读到——想验证空库，请换一个干净的 `HOME`。

## 五条硬口径

这些都写在 SKILL.md 里，是踩出来的，不是想出来的：

1. **别信嘴，信账**。工具说"记了/拦了/改了"，必须有一条断言去读结果才算数；负向用例必须同时断言退出码和文案——只看文案，会把"文案说拒绝了、退出码是 0"当成拦住了。
2. **一个功能只留一个工具**。职能重叠的多个工具，最后只保留最新那份，其余的砍掉、数据合并转移。
3. **会变的东西放持久盘，不变的东西放安装位**。库住持久卷，程序留技能目录；容器重置时库不会跟着回滚成残库。
4. **记账前先确认库在哪台机**（`recall.py where`）。多台机器同写一座库，号会撞、账会分叉——要么只让一台写，要么每台各用各的库。
5. **空库上 `gate` 退出码 2 是正常**。0 根探针不等于通过，空闸不算过闸。

## 空库版的三件"看着像坏了、其实正常"

1. `recall.py gate` 报「GATE 无法判定：0 根探针」并 exit 2 —— 设计如此。
2. `deploy_check.py` 报「批准表不可用」—— 0 张卡就没有探针可批，建卡并 `approve` 之后才会绿。
3. 资产册是空的 —— 它是"本机扫描结果"，换台机器扫出来必然不同，所以包里故意不带。跑一次 `asset scan` 就有了。
